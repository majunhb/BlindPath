```
│   ├── ADR/                     ← 新建（架构决策记录目录）

│       ├── module_obstacle.md   ← 新建

├── app/libs/README.md           ← 保留
└── 修复说明.md                  ← 建议移入 docs/ 并链接 CHANGELOG
```

### 6.2 文档编写原则（针对本项目）

1. **README 优先** — 投入最多精力到 README，这是第一印象
2. **接口必有 KDoc** — 所有 `Repository` 接口方法必须有完整 KDoc
3. **文档与代码同库** — 保持 docs/ 在代码仓库中，随 PR 一起审查
4. **PR 检查清单加文档检查项** — 在 CONTRIBUTING.md PR 清单中强化文档要求
5. **半年审一次** — 对 docs/ 目录下的文档每半年做一次过期检查

### 6.3 KDoc 写作规范

对于本项目，建议所有接口方法采用以下格式：

```kotlin
/**
 * 执行障碍物检测启动
 *
 * 加载 AI 模型（失败时进入演示模式），启动 CameraX 摄像头，
 * 开始实时帧分析。
 *
 * @return Result.Success(true) 启动成功
 *         Result.Error(message) 启动失败，含错误描述
 *
 * ## 演示模式
 * 当 AI 模型文件 (yolov8n.tflite) 不存在时，
 * 摄像头仍可启动，但检测结果为空列表。
 */
suspend fun startDetection(): Result<Boolean>
```
